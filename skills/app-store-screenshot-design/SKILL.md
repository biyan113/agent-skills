# App Store Screenshot Design Skill

## 1. 技能目标

将一个已经完成或正在开发的 iOS/iPadOS 应用，整理为一套可直接交付给设计师、Figma、图像生成模型或前端原型工具使用的 App Store 上架宣传截图方案。

最终方案必须同时满足：

1. 用户在 1～2 秒内看懂产品价值。
2. 前 3 张截图完成主要转化说服。
3. 每张截图只表达一个核心卖点。
4. 宣传图以真实 App 界面为主体，不制作与产品无关的纯概念海报。
5. 风格统一，但每张图的构图和信息重点不机械重复。
6. 便于后续制作中文、英文及其他语言版本。
7. 在实际上架前，优先核对 Apple 官方最新截图规格与审核要求。

---

## 2. 适用场景

当用户提出以下需求时启用本技能：

- 设计 App Store 上架截图
- 规划 iOS 应用宣传图
- 汇总 App Store 截图风格
- 为应用生成 6 张或 10 张商店宣传图
- 输出 Figma 截图设计稿说明
- 为不同国家和语言制作商店截图
- 优化现有 App Store 截图转化率
- 为 App Store 产品页优化准备 A/B 测试版本
- 根据现有 UI 截图生成宣传图布局

本技能主要面向：

- iPhone App
- iPad App
- Apple Watch 配套 App
- macOS App 的 App Store 产品页

如用户明确只需要 Google Play 宣传图，应切换到 Android 商店宣传图规则，不要直接套用本技能。

---

## 3. 必要输入

尽量收集以下信息；缺少次要信息时可基于合理假设继续输出，不要阻塞任务。

### 3.1 产品信息

- App 名称
- 一句话定位
- 目标用户
- 核心问题
- 最强功能
- 与同类产品的差异
- 是否订阅制或一次性付费
- 是否强调隐私、本地处理、离线能力

### 3.2 视觉信息

- App 图标
- 品牌色
- 现有 UI 截图
- 深色模式或浅色模式
- 是否有人物、插画、吉祥物或品牌角色
- 用户偏好的宣传图风格

### 3.3 上架信息

- 目标设备：iPhone、iPad 或多设备
- 目标语言和地区
- 计划制作的截图数量
- 是否准备产品页优化测试
- 是否需要 App Preview 视频

---

## 4. 默认决策原则

当用户没有指定具体风格时，默认采用以下组合：

> 极简产品展示 + 大字价值主张 + 真实 UI 放大 + 轻量品牌渐变

默认截图数量为 6 张。

默认截图结构：

1. 核心结果
2. 最强功能
3. 实际操作
4. 差异化优势
5. 效率或成果
6. 隐私与可信度

默认信息原则：

> 一个截图，一个卖点，一个视觉中心。

默认视觉比例：

- 真实 UI：60%～75%
- 主标题：15%～25%
- 品牌背景与装饰：10%～20%

---

## 5. 2026 年主流风格库

### 5.1 极简产品展示型

特征：

- 暖白、浅灰、浅蓝或低饱和背景
- 正面设备或直接展示屏幕内容
- 大标题、少文字、大留白
- UI 是画面主体
- 装饰元素克制

适合：

- 效率工具
- 笔记
- 日历
- 提醒
- 翻译
- 系统工具
- 独立开发者产品

风险：

- 容易模板化
- 需要通过字体、构图、品牌色和 UI 局部建立辨识度

---

### 5.2 大字价值主张型

核心规则：

- 先写用户得到的结果
- 不优先写技术名词
- 中文标题控制在 6～14 个字
- 英文标题控制在 3～7 个单词
- 每张图只保留一个主标题

错误示例：

- AI 智能分析功能
- 多模型协同处理
- 支持多种格式

推荐示例：

- 一分钟整理全部照片
- 说完，文字就整理好了
- 不用逐张找，重复照片自动出现
- 会议结束，纪要已经整理好

---

### 5.3 UI 放大型

特征：

- UI 占画面 70%～90%
- 手机边框弱化或省略
- 使用局部放大突出核心操作
- 标题通常只有一行
- 不堆叠复杂装饰

适合：

- 系统监控
- 开发者工具
- 数据分析
- 专业照片编辑
- 音视频剪辑
- 日历和任务管理

---

### 5.4 连屏叙事型

将前 3～5 张截图设计为连续故事：

> 发现问题 → 自动处理 → 获得结果

常见连接方式：

- 连续渐变
- 地图路线
- 横跨多屏的图形
- 同一个角色或人物
- 连续背景场景
- 巨型文字跨屏

要求：

- 多张并排时有整体感
- 单张独立出现时仍能看懂
- 不允许某张截图完全依赖前后图才能理解

---

### 5.5 深色科技型

特征：

- 黑色、藏蓝、深紫背景
- 白色高对比文字
- 青蓝、绿色或紫色局部高亮
- 数据图表、波形、网格和少量发光
- 专业、克制、可信

适合：

- AI 工具
- 金融
- 密码安全
- VPN
- 网络工具
- 系统监控
- 开发者工具

避免：

- 大面积蓝紫宇宙背景
- 发光机器人
- 与产品功能无关的粒子球
- 过度霓虹光效
- 所有截图都使用同一套 AI 模板

---

### 5.6 卡片悬浮型

特征：

- 手机或主 UI 位于中心
- 搜索框、结果卡片、通知卡片在周围悬浮
- 使用轻阴影、模糊和半透明层次
- 展示功能关系，而不是单纯装饰

适合：

- AI 助手
- 效率工具
- 健康管理
- 数据管理
- 自动化工具

规则：

- 悬浮卡片必须来自真实功能
- 不能虚构 App 中不存在的组件
- 玻璃效果只用于局部
- 不能因为透明而降低标题和 UI 可读性

---

### 5.7 生活场景摄影型

特征：

- 真人或手部
- 自然光
- 真实使用环境
- App 与生活场景结合
- 摄影质感自然，不像传统广告棚拍

适合：

- 健身
- 旅行
- 购物
- 家庭
- 教育
- 本地生活
- 社交

可用场景：

- 通勤时背单词
- 跑步后查看运动记录
- 旅行中规划路线
- 家庭成员查看共享清单
- 创作者在手机上完成剪辑

---

### 5.8 品牌插画型

特征：

- 角色、吉祥物或品牌插画
- 鲜明色块
- 情绪友好
- 可形成连续故事

适合：

- 儿童教育
- 语言学习
- 睡眠冥想
- 习惯养成
- 心理健康
- 游戏化工具

规则：

- 插画不能完全替代真实 UI
- 前 3 张中至少有 2 张清楚展示实际产品页面
- 角色的动作要与功能或用户结果相关

---

### 5.9 结果先行型

第一张优先展示最终成果，而不是首页或设置页。

适合：

- 修图
- 视频剪辑
- 音频转录
- 扫描
- AI 生成
- 文件整理
- 健身报告

常见结构：

1. 最终结果
2. 核心操作
3. 自动化能力
4. 差异化优势
5. 效率收益
6. 隐私或可信度

---

### 5.10 前后对比型

常见形式：

- Before / After
- 左右分屏
- 上下分屏
- 两台设备对照
- 整理前与整理后
- 模糊与清晰
- 手工处理与自动处理

适合：

- 照片清理
- 修图
- 扫描
- 翻译
- 文件整理
- 系统优化
- 效率工具

规则：

- 对比必须来自真实能力
- 不夸大处理结果
- 不使用无法稳定复现的效果

---

### 5.11 杂志海报型

特征：

- 大面积摄影
- 强排版
- 不对称网格
- 大字和小字形成强烈比例
- UI 作为画面的一部分

适合：

- 音乐
- 阅读
- 新闻
- 摄影
- 时尚
- 旅行
- 菜谱
- 内容平台

风险：

- 容易变成纯品牌海报
- 真实 UI 展示不足

建议：

- 前 3 张中至少有 2 张让 UI 占画面三分之一以上

---

### 5.12 复古与手作型

特征：

- 纸张纹理
- 胶带
- 手写标注
- 拼贴
- 像素图标
- 颗粒
- 旧系统窗口

适合：

- 创意工具
- 年轻品牌
- 独立应用
- 日记
- 相机
- 音乐

不适合：

- 金融
- 密码安全
- 企业管理
- 医疗高可信场景

---

## 6. 品类选择矩阵

### 6.1 AI 与效率工具

推荐组合：

> 极简产品展示 + UI 放大 + 卡片悬浮 + 局部深色科技感

重点展示：

- 输入前后变化
- 自动整理能力
- 节省时间
- 可控性
- 隐私

避免：

- 机器人
- 脑形图标
- 过量紫色粒子
- 抽象模型概念

---

### 6.2 照片与视频工具

推荐组合：

> 结果先行 + 前后对比 + 全屏作品 + 简洁操作界面

重点展示：

- 处理结果
- 操作简单
- 处理速度
- 支持格式
- 本地处理

---

### 6.3 教育与语言学习

推荐组合：

> 品牌角色 + 鲜明色块 + 真实练习页面 + 连屏故事

推荐叙事：

> 认识 → 练习 → 拼写 → 对话 → 坚持

重点展示：

- 学习路径
- 即时反馈
- 成就感
- 连续学习
- 个性化内容

---

### 6.4 健康、睡眠与习惯

推荐组合：

> 温暖插画 + 柔和摄影 + 浅色卡片 + 数据成果

重点展示：

- 轻松使用
- 日常陪伴
- 趋势数据
- 习惯变化
- 隐私保护

---

### 6.5 金融、密码与安全

推荐组合：

> 深色高对比 + 数据 UI + 专业排版 + 隐私证明

重点展示：

- 本地保存
- 加密方式
- 权限范围
- 风险提示
- 数据可控

禁止使用：

- 百分百安全
- 永不泄露
- 绝对匿名
- 军用级安全

除非有明确、可验证的技术和合规依据。

---

### 6.6 系统工具与开发者工具

推荐组合：

> UI 放大型 + 极简黑白 + 数据图表 + 局部高亮

重点展示：

- 信息密度
- 实时数据
- 快捷操作
- 性能占用
- 本地运行
- 专业设置

---

### 6.7 社交与内容社区

推荐组合：

> 真实内容 + 真人摄影 + UGC 质感 + 多内容卡片

重点展示：

- 用户能看到什么
- 用户能发布什么
- 互动方式
- 社区氛围
- 内容质量

---

### 6.8 游戏

推荐组合：

> 游戏画面铺满 + 核心角色 + 实际玩法 UI + 奖励反馈

规则：

- 第一张可以展示世界观
- 第二张必须尽快展示真实玩法
- 不允许整套截图都是 CG 或概念海报

---

## 7. 截图叙事工作流

### 步骤 1：提炼一句话定位

使用公式：

> 帮助【目标用户】在【场景】中，通过【核心能力】获得【结果】。

示例：

> 帮助照片很多的 iPhone 用户，通过本地智能识别，快速清理重复和相似照片。

---

### 步骤 2：提炼三个主要卖点

必须优先选择：

1. 用户最关心的结果
2. 最能体现产品差异的功能
3. 最能建立信任的证据

不要按开发模块顺序排列。

---

### 步骤 3：选择主风格和辅助风格

每套截图只选择：

- 1 个主风格
- 1～2 个辅助风格

示例：

- 主风格：极简产品展示型
- 辅助风格：结果先行型、前后对比型

避免同时混用 4 种以上视觉语言。

---

### 步骤 4：设计前 3 张截图

前 3 张必须完成：

1. 说清楚产品价值
2. 证明产品真的能做到
3. 给出下载理由

推荐结构：

- 第 1 张：核心结果
- 第 2 张：最强功能
- 第 3 张：真实操作

---

### 步骤 5：补充后续截图

推荐：

- 第 4 张：差异化能力
- 第 5 张：效率、数据或成果
- 第 6 张：隐私、离线或可信度
- 第 7 张：个性化
- 第 8 张：跨设备或系统能力
- 第 9 张：高级功能
- 第 10 张：完整品牌收束

---

### 步骤 6：生成文案

文案必须按以下顺序优先：

1. 结果型
2. 场景型
3. 对比型
4. 功能型

每张截图最多：

- 1 个主标题
- 1 个可选辅助说明
- 0～2 个必要标签

不要在宣传图中复制整段产品描述。

---

### 步骤 7：生成版式说明

每张截图必须写明：

- 背景
- 主标题位置
- UI 类型
- UI 占比
- 设备角度
- 装饰元素
- 视觉中心
- 与上一张的衔接方式

---

### 步骤 8：生成本地化方案

本地化不是逐字翻译。

需要检查：

- 文案长度
- 语言习惯
- 地区常见表达
- 数字、日期和单位
- 文化元素
- 截图中的真实内容

中文标题建议 6～14 个字。

英文标题建议 3～7 个单词。

日文、韩文、德文等较长文本需要准备独立排版版本。

---

### 步骤 9：核对官方规格

在正式输出尺寸和文件格式前，必须优先核对 Apple 官方最新文档。

需要确认：

- 当前支持的截图设备规格
- 每个设备可上传的截图数量
- 文件格式
- 分辨率
- 是否允许透明通道
- App Preview 视频规格
- 产品页优化规则
- 自定义产品页规则

不要依赖过期博客或旧版尺寸表作为最终依据。

---

## 8. 标题生成规则

### 8.1 结果型

公式：

> 【动作或能力】+【用户结果】

示例：

- 一键清理重复照片
- 说完自动整理成稿
- 会议结束，纪要已经完成
- 快速找到最重要的信息

---

### 8.2 场景型

公式：

> 【场景】+【完成的事情】

示例：

- 通勤路上也能练习口语
- 开会时自动记录重点
- 出门前快速安排今天

---

### 8.3 对比型

公式：

> 不用【旧方式】+【新结果】

示例：

- 不用逐张找，重复照片自动出现
- 不用整理，录音自动变成纪要
- 不用切换多个工具

---

### 8.4 功能型

公式：

> 【核心功能】+【限制或优势】

示例：

- 本地识别相似照片
- 实时显示 CPU 与 GPU 状态
- 离线完成音频转录

---

## 9. 视觉设计规范

### 9.1 字体

中文优先：

- 苹方
- 思源黑体
- 品牌定制黑体

字体层级：

- 主标题：100%
- 辅助说明：35%～45%
- UI 原生文字：必须可读，但不能与主标题争夺注意力

一套截图最多使用：

- 1 个主字体家族
- 2～3 个字重

---

### 9.2 配色

推荐四种基础方案：

#### 暖白低饱和

适合：效率、笔记、生活、健康。

#### 高饱和品牌色

适合：教育、社交、娱乐、年轻品牌。

#### 深色专业配色

适合：AI、金融、安全、系统工具。

#### 柔和渐变

适合作为背景，不应成为唯一视觉主体。

---

### 9.3 设备模型

推荐：

- 正面或轻微透视
- 保持设备比例真实
- 不过度倾斜
- 不让设备边框压缩 UI 可读面积

避免：

- 设备角度超过 20～25 度
- 设备模型比真实 UI 更抢眼
- 多台设备无意义堆叠
- 设备阴影过重

---

### 9.4 背景与装饰

背景只能承担以下作用：

- 强化品牌色
- 建立层次
- 连接多张截图
- 衬托 UI
- 表达场景

背景不能：

- 替代产品信息
- 比 UI 更抢眼
- 包含与功能无关的 AI 装饰
- 使用过多 3D 漂浮物

---

## 10. 6 张截图标准模板

### 第 1 张：核心价值

目标：用户立即知道这个 App 有什么用。

输出内容：

- 主标题
- 最终结果或最核心 UI
- 品牌识别

---

### 第 2 张：最强功能

目标：给出主要下载理由。

输出内容：

- 核心功能界面
- 简短结果文案
- 必要时使用局部放大

---

### 第 3 张：真实操作

目标：证明产品不是概念。

输出内容：

- 真实操作路径
- 手势、按钮或流程
- 减少装饰

---

### 第 4 张：差异化优势

目标：解释为什么选择本产品。

输出内容：

- 独有能力
- 更快、更简单、更隐私或更专业
- 必须有真实证据支持

---

### 第 5 张：效率或成果

目标：强化使用后的收益。

输出内容：

- 节省时间
- 释放空间
- 生成报告
- 形成习惯
- 数据变化

---

### 第 6 张：隐私与可信度

目标：降低下载和付费顾虑。

输出内容：

- 本地处理
- 离线能力
- 数据不上传
- 无广告
- 权限透明
- 订阅说明

只展示实际具备的能力。

---

## 11. 输出格式

每次使用本技能时，默认输出以下结构。

### A. 产品定位摘要

- App 名称
- 目标用户
- 核心问题
- 核心价值
- 主要差异化

### B. 推荐视觉方向

- 主风格
- 辅助风格
- 选择原因
- 不推荐的风格

### C. 截图叙事顺序

用一行概括：

> 核心结果 → 最强功能 → 实际操作 → 差异化 → 使用成果 → 隐私可信

### D. 每张截图设计说明

使用以下格式：

#### 截图 1：标题

- 目标：
- 主标题：
- 辅助说明：
- 展示页面：
- 构图：
- 背景：
- UI 占比：
- 装饰元素：
- 与下一张衔接：

### E. 文案备选

为前 3 张分别提供：

- 默认版
- 更直接版
- 更品牌化版

### F. 设计 Token

至少包含：

- 背景色
- 主文字色
- 辅助文字色
- 品牌强调色
- 字体
- 标题字号比例
- 圆角
- 阴影

### G. 本地化建议

- 中文排版

- 是否需要单独调整 UI 内容

### H. 上架验收清单

逐项列出是否通过。

## 12. A/B 测试方案

当用户需要产品页优化时，至少设计 3 个首屏方向。

### A 版：结果优先

- 第一张直接展示最终效果
- 适合功能结果明显的产品

### B 版：功能优先

- 第一张展示最强操作界面
- 适合专业工具

### C 版：场景优先

- 第一张展示目标用户和使用环境
- 适合生活方式、教育、健康和旅行应用

测试时尽量只修改一个主要变量：

- 首张文案
- 首张构图
- UI 占比
- 场景图
- 品牌色

不要一次同时更改所有元素，否则无法判断转化差异来自哪里。

---

## 13. 禁止事项

不得输出以下方案：

1. 纯启动页作为主要截图。
2. 纯登录页作为主要截图。
3. 整套都是概念插画或 CG。
4. 展示 App 中不存在的功能。
5. 夸大 AI、清理、修复或安全效果。
6. 每张图堆叠 3 个以上功能点。
7. 使用长段落说明。
8. 只展示倾斜手机模型，不说明用户价值。
9. 用机器人、粒子、发光球代替真实产品。
10. 所有截图使用完全相同的构图。
11. 因追求玻璃效果导致标题或 UI 难以阅读。
12. 未核对 Apple 官方最新规格就给出绝对尺寸结论。

## 14. 验收清单

### 内容

- [ ] 第一张能在 2 秒内看懂
- [ ] 前 3 张完成主要转化说服
- [ ] 每张只表达一个卖点
- [ ] 文案以用户结果为主
- [ ] 没有虚构功能
- [ ] 没有过度承诺

### 视觉

- [ ] 真实 UI 是画面主体
- [ ] 字体和品牌色统一
- [ ] 标题在缩略图状态下仍可读
- [ ] UI 关键内容没有被设备边框遮挡
- [ ] 装饰没有抢夺视觉中心
- [ ] 多张并排时有连贯性
- [ ] 单张独立看也能理解

### 本地化

- [ ] 中文没有生硬翻译感
- [ ] 英文标题长度适中
- [ ] 长文本语言不会溢出
- [ ] UI 中的内容与目标地区一致
- [ ] 日期、货币、单位和格式正确

### 上架

- [ ] 已核对 Apple 官方最新截图规格
- [ ] 尺寸和设备类型正确
- [ ] 文件格式正确
- [ ] 不含不支持的透明通道
- [ ] 截图与当前版本功能一致
- [ ] App Preview 与截图内容一致

## 15. 默认最终回答示例

用户输入：

> 为一个本地照片去重 App 设计 6 张 App Store 宣传图。

技能应输出：

1. 产品定位摘要
2. 推荐主风格：极简产品展示型
3. 辅助风格：结果先行型、前后对比型
4. 六张截图叙事顺序
5. 每张截图的标题、UI 页面、构图、背景和衔接方式
6. 前三张文案的三套版本
7. 品牌色和排版 Token
8. 中文与英文适配建议
9. 上架验收清单

推荐叙事示例：

1. 快速找到所有重复照片
2. 自动识别相似与连拍照片
3. 滑动选择，几秒完成清理
4. 智能保留更清晰的那一张
5. 释放空间，让相册重新整洁
6. 完全本地处理，照片不会上传

## 16. 最终原则

任何截图方案都必须遵循：

> 先让用户看懂价值，再展示功能；先证明真实，再强化品牌。

> 宣传图不是功能说明书，而是一个按顺序完成说服的产品故事。

> 2026 年最稳妥的主流方向，不是堆叠更多效果，而是使用更少、更清楚、更真实的视觉信息。
